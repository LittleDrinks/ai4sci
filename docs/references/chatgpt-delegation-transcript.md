## 真正的根原则

> **不要试图让 LLM 变得值得信任；要让整个系统不需要预先信任 LLM。**

更具体地说：

> **任何模型输出默认都只是候选。只有当它被转换为可外部检查的对象，并通过与生成模型错误来源不同的验证，才能升级为知识或行动。**

可以再压缩成一句：

> **LLM 负责扩张可能性空间，科学机制负责压缩可能性空间。**

所以，黑盒并不是最根本的问题，**自证才是根本问题**。

人的大脑同样是黑盒。科学从来不是因为我们能检查科学家的神经元才相信他，而是因为他必须把证据、方法、预测、实验和失败条件公开出来，让其他人能够复核。一个 LLM 可以是黑盒，但它不能同时担任：

-   假设生成者；

-   文献选择者；

-   证据解释者；

-   实验设计者；

-   结果评审者；

-   最终裁决者。


那相当于让一个黑盒给自己出题、自己考试、自己阅卷。

# 一、凭什么相信 LLM 生成的答案？

答案是：**不应该相信“答案”这个对象。**

系统不应该输出一个自然语言答案，然后附上若干引用；系统应该输出一个具有明确状态的**科学主张**。

例如，一个主张只能处于以下状态之一：

```
未验证提议
→ 已找到来源
→ 来源确实支持
→ 推导可以复现
→ 经替代方法验证
→ 经独立数据验证
→ 经物理实验验证
→ 经独立重复验证
```

信任的对象不是句子，而是它携带的“主张证书”：

```
Claim Certificate
├── 原子化主张
├── 当前状态
├── 支持证据
├── 反对证据
├── 文献覆盖范围与遗漏风险
├── 隐含假设
├── 可执行推导或分析代码
├── 预测的可观察结果
├── 已通过的独立验证器
├── 已知失效条件
└── 尚未解决的不确定性
```

其中，**LLM 自己报告的 confidence 不具有科学意义**。你目前的方案让模型给证据抽取、相关性判断和假设打置信度分数。

efb2e131-1701-415f-bbdf-8f11d74…

这类分数反映的是模型对自己文本判断的稳定程度，不等于科学主张为真的概率。

真正的置信度必须来自：

-   同类任务上的历史校准；

-   数据规模与统计功效；

-   研究设计质量；

-   多种独立测量是否一致；

-   对替代解释的排除程度；

-   独立复现情况。


因此系统最终不应该说：

> “AI 认为这个假设有 87% 的可信度。”

而应该说：

> “该主张有三项独立证据支持、一项相反结果；主要结论依赖假设 A；目前尚未经过实验室 B 的独立复现。”

# 二、凭什么按照 LLM 的方案做实验？

同样，不应该因为“LLM 推荐”而做实验。

LLM 只能提出候选实验。真正允许实验进入执行队列的对象，应该是一个**实验许可证明**：

```
Experiment Warrant
├── 这项实验准备消除哪个不确定性
├── 当前有哪些竞争解释
├── 每个解释分别预测什么结果
├── 为什么该实验能够区分它们
├── 与其他候选实验相比的优势
├── 对照组、样本量、统计功效
├── 仪器与材料配置的来源
├── 可行性和前置条件
├── 成本、风险与可逆性
├── 最小规模先导实验
├── 中止条件
└── 独立评审结果
```

实验执行的理由不再是：

> “LLM 认为这个实验有前景。”

而是：

> “在目前存活的三个解释中，这个实验以最低成本产生最大的可区分结果，并且其配置已由文献、仪器约束、统计功效分析和领域专家分别核验。”

一篇在 **2026 年 8 月 4 日**发布的新预印本，用 19 个领域、300 篇论文评估实验设计，报告多数 LLM 不能直接产生高质量实验方案；共同瓶颈不是宏观研究叙事，而是数据集、基线、指标和具体配置。搜索模式也没有稳定解决这个问题。该研究仍是新预印本，而且部分评分使用经过人工一致性检查的 LLM judge，因此结论应继续复核，但它至少说明“让模型多搜索一下”不是实验设计可信性的充分条件。[![](https://www.google.com/s2/favicons?domain=https://arxiv.org&sz=128)arXiv+2![](https://www.google.com/s2/favicons?domain=https://arxiv.org&sz=128)arXiv+2](https://arxiv.org/html/2608.03501v1)

所以，高层实验创意可以由 LLM 提出；低层配置必须经过数据库、实验室 SOP、设备能力、统计代码和专家经验的逐项落地。

# 三、你缺少的不是普通 self-reflect，而是“外部化反思”

你当前想到的 self-reflect 很重要，但需要重新定义。

同一个模型重新阅读自己的回答，并不会自然获得新的信息。已有研究发现，在没有外部反馈时，LLM 的内在自我修正经常无效，甚至会把正确答案改错。[![](https://www.google.com/s2/favicons?domain=https://arxiv.org&sz=128)arXiv](https://arxiv.org/abs/2310.01798)

多智能体也不天然解决问题。实验显示，模型辩论可能因为迎合、从众和错误说服而逐步降低准确率，甚至更强的模型会被较弱模型带向错误答案。[![](https://www.google.com/s2/favicons?domain=https://arxiv.org&sz=128)arXiv](https://arxiv.org/html/2509.05396v2)

更直接的是一项 2026 年对八个科学领域、超过 25,000 次 agent 运行的研究：在该研究设置中，68% 的轨迹没有真正吸收获得的证据，只有 26% 出现了由反证驱动的信念修正；基础模型解释的行为差异显著高于 agent scaffold。[![](https://www.google.com/s2/favicons?domain=https://arxiv.org&sz=128)arXiv](https://arxiv.org/abs/2604.18805)

因此：

> **没有引入新证据，或者没有引入不同错误通道的验证器，就不应叫反思。**

有效的系统级反思至少有四种：

1.  **反向文献反思**：不是继续寻找支持材料，而是专门检索反例、失败实验、系统综述和相互冲突的研究。

2.  **独立推导反思**：用不同代码实现、不同模型、不同分析方法或不同数据切分重新得到结论。

3.  **反事实反思**：明确写出“如果假设是错的，我们应该看到什么”，然后主动寻找这种结果。

4.  **现实反馈反思**：使用保留数据、模拟器、仪器或真实实验，让外部世界改变系统状态。


一个非常简单的工程判据是：

> **如果一次 reflect 之后，证据图、假设集合、预测或不确定性都没有发生可解释的变化，这次 reflect 只是 token 循环。**

# 四、文献调研不能只是 RAG 模块

当前方案说“真正的难点不是检索，而是证据质量”。

efb2e131-1701-415f-bbdf-8f11d74…

这需要反过来理解：**科学文献检索本身就是尚未解决的核心研究问题。**

2026 年的 AutoResearchBench 对复杂科学文献发现进行评估，最好的被测系统在其深度检索和广度检索指标上仍低于 10%；增加推理步骤和工具调用没有带来稳定提升，长轨迹有时只是产生更多无效搜索。[![](https://www.google.com/s2/favicons?domain=https://arxiv.org&sz=128)arXiv+1](https://arxiv.org/html/2604.25256v1)

与此同时，在边界更清晰的任务上，经过专门设计的 PaperQA2 又能够在若干文献问答、总结和矛盾发现任务上达到或超过受测专家。[![](https://www.google.com/s2/favicons?domain=https://arxiv.org&sz=128)arXiv](https://arxiv.org/abs/2409.13740?utm_source=chatgpt.com)

这两个结果并不矛盾。它们共同说明：

> **LLM 能力是锯齿状的，不能从一个任务上的优秀推断到整个“文献调研能力”都可靠。**

所以你的文献层应该接近系统综述基础设施，而不是普通 RAG：

```
研究问题和检索协议预注册
→ 多数据库检索
→ 全文索引
→ 引文前向/后向追踪
→ 明确纳入与排除标准
→ 保留排除日志
→ 估计覆盖率与遗漏风险
→ 提取研究设计、样本、效应量和局限
→ 构造支持/冲突/不可比较关系
→ 专门记录负结果和未发表失败经验
```

LLM 可以帮助生成检索式、筛选候选、抽取字段和发现矛盾，但不能自己宣布“文献已经调研充分”。

# 五、基模不断进化时，系统真正应该抓住什么不变量？

不变量不是某一种 prompt，不是 ReAct，不是多智能体，也不是当前模型的缺陷清单。

真正的不变量是一个**模型无关的科学可信内核**。

```
原始问题
    ↓
Research Contract：什么算进展，什么不算
    ↓
候选生成器：一个或多个可替换的 LLM
    ↓
Claim / Evidence / Assumption Graph
    ↓
异质验证器组合
├── 文献与数据库
├── 规则和约束求解器
├── 数学证明器
├── 代码测试
├── 模拟器
├── 统计分析
├── 仪器和真实实验
└── 人类专家
    ↓
Decision Gate
    ↓
执行、观察、信念更新
    ↓
同时更新模型在该任务类型上的可靠性记录
```

这个内核应该遵守五条硬规则：

### 1\. Token 默认没有知识地位

LLM 生成的内容只能进入候选区，不能直接写入事实库、结论库或仪器执行队列。

### 2\. 生成权和裁决权必须分离

同一个模型可以参与讨论，但不能成为自己输出的唯一验证者。使用多个模型只有在实测证明它们的错误具有互补性时才增加可信度；换几个名字相同、训练分布相似的 agent，不等于独立复核。

### 3\. 自主程度由验证器决定，而不是由模型版本决定

可以定义：

允许自主度∝风险×成本×不可观测性验证器强度×可逆性​

它不是用于精确计算的公式，而是架构规则。

-   数学证明、代码测试、有明确指标的模拟优化：可以高自主；

-   现有数据上的统计研究：可以中等自主；

-   真实实验：先导实验、专家和安全审批；

-   没有近期验证器的宇宙学、意识、生命起源等问题：只能生成知识地图、竞争解释和研究提案，不能自动宣布答案。


### 4\. 模型可信度必须是任务局部的

不能记录“模型 A 很可靠”，而应记录：

```
模型 A
├── 文献元数据抽取：97%
├── 复杂纳入标准筛选：71%
├── 因果结论判断：54%
├── 实验高层规划：较强
├── 仪器参数配置：较弱
└── 反证后修正率：待测
```

新基模进入系统时，不是直接替换旧模型，而是先在隐藏任务、历史科研轨迹和影子运行中测量，再逐项授予权限。

### 5\. 系统状态必须存在模型之外

问题定义、证据、假设、预测、失败记录、实验结果和信念变化都必须存放在外部结构中。更换 GPT、Claude、Gemini 或未来模型，不应该丢失系统的科学状态。

这正是你面对“基模不断进化”时最重要的答案：

> **能力是可替换插件，科学权利是固定协议。**

# 六、125 个大问题不应该共享同一条 agent 流程

它们应该共享同一个可信内核，但不能共享同一种自主度。

系统首先不是问：

> “LLM 应该怎样回答这个问题？”

而是问：

> “这个问题的哪些局部命题，在当前技术条件下能够被什么外部对象裁决？”

可以把每个大问题拆成一张“可验证性地图”：

```
大问题
├── 已知事实，可直接核验
├── 存在争议，可做系统综述
├── 可由现有数据区分
├── 可由模拟或计算区分
├── 可由近期实验区分
├── 依赖尚不存在的仪器
├── 依赖尚不存在的理论语言
└── 暂时没有可靠裁决机制
```

你的系统不是承诺“回答 125 个大问题”，而是：

> **持续把大问题转化为当前能够被现实裁决的最小研究单元，同时诚实地保留无法裁决的部分。**

这比一个统一的“问题卡片—假设—实验—结论”流程更加本质。

# 七、AI 真正稳定的长处是什么？

不是它天然更接近真理。

AI 比较稳定的优势是：

-   大规模并行浏览和整理；

-   跨领域概念重组；

-   快速生成大量候选；

-   持续维护复杂外部状态；

-   编写和修改代码；

-   在低成本环境中反复搜索；

-   在明确反馈下快速优化。


可以把它概括为：

> **AI 的长期优势是搜索经济学，而不是认识论权威。**

成功案例也基本遵循这一边界。

Google 的 AI co-scientist 可以生成和排序生物医学假设，但其内部 Elo 评价并不是独立真值；真正赋予部分提议可信度的是专家参与、计算生物学验证和体外实验。[![](https://www.google.com/s2/favicons?domain=https://research.google&sz=128)Google Research](https://research.google/blog/accelerating-scientific-breakthroughs-with-an-ai-co-scientist/)

A-Lab 能在 17 天内完成 353 次材料实验并实现 36 个目标材料，是因为它工作在一个目标明确、XRD 可以反馈、主动学习可以更新、实验结果最终还能人工复核的封闭环境中。[![](https://www.google.com/s2/favicons?domain=https://www.nature.com&sz=128)Nature](https://www.nature.com/articles/s41586-023-06734-w)

这说明最有前途的结构不是：

> LLM 思考得越来越像科学家。

而是：

> LLM 在一个反馈真实、权限受控、证据外显、错误能够被环境捕获的科研环境中，进行比人类更大规模的搜索。

保留这些部分：

-   provenance；

-   确定性统计；

-   仪器适配；

-   审计；

-   复现；

-   人类对高风险节点负责。

降级这些部分：

-   persona；

-   多智能体辩论；

-   LLM confidence；

-   反方 agent；

-   LLM-as-judge；

-   “当前证据最强结论”。


它们只能是候选生成和搜索策略，不能构成可信性基础。

增加六个真正的核心模块：

1.  系统综述级文献引擎；

2.  模型外部的主张—证据—假设图；

3.  Claim Certificate；

4.  Experiment Warrant；

5.  外部化反思与独立验证器；

6.  任务级模型校准和动态权限系统。


## 最终定位

> **我们不是构建一个值得相信的 AI 科学家，而是在构建一套不依赖任何单个模型可信性的科学操作系统。LLM 作为可替换的候选生成与搜索策略，负责扩大人类能够探索的假设、文献和实验空间；系统通过模型外部的证据结构、预注册、独立验证、现实反馈、持续校准和人类责任机制，决定哪些内容可以升级为科学主张，哪些方案可以获得实验资源。基模可以持续进化，但生成与裁决分离、证据优先、权限随可验证性分配，是系统不变的内核。**

最关键的一句话是：

> **不要继续问怎样证明 LLM 可靠；要问怎样让 LLM 的不可靠性被系统吸收，而不污染科学知识和现实行动。**

形式上，不是问“这个模型准确率是多少”，而是对每一种科研任务 t 求：

cmax​ Coveraget​(c)

满足：

Riskt​(c)≤ϵt​ CAI​+Caudit​+P(error)Cerror​<Chuman​ AgentLift\=Utility(agent)−Utility(fixed pipeline)\>0

这里：

-   **Coverage**：多少比例的工作可以不经逐项人工审核而直接通过；

-   **Risk**：在自动通过的那部分结果里，错误率有多高；

-   **AgentLift**：Agent 循环是否真的优于固定流程或单次调用；

-   **Net Value**：节省的人力是否大于计算、审核和错误代价。


这才是“大概率可以信任”的工程定义。

# 不是审核每个 token，而是验收少量边界产物

你的系统不应该审查 Agent 的每一步思考。

Agent 可以在内部搜索一千次、写一百份代码、尝试五十个方案。系统只检查它准备改变外部科学状态的少数边界对象：

-   准备写入证据库的结构化事实；

-   准备升级为正式主张的结论；

-   准备消耗真实实验资源的实验单；

-   准备进入下一阶段的代码、模型或候选材料。


因此，应该采用一句非常具体的设计原则：

> **搜索可以开放，写入必须受控。**

或者更完整地说：

> **允许 Agent 在有外部反馈的空间里自由搜索和试错；只对通过低成本验收并达到任务级风险阈值的结果，开放“写入科学状态”和“消耗现实资源”的权限。**

这样，系统不是逐 token 审核，而是像编译器、优化器、自动实验平台一样，**忽略大量内部失败，只验收最终候选**。

# 这篇实验设计论文并没有证明 LLM 无法用于 AI4S

它更准确地证明了：

> **“完整实验设计”是一个过大的委托单元。**

在 SCOPE 的 300 个机器学习论文任务中，模型平均只有 14.81/30；低层配置——数据集、基线和指标——明显弱于高层实验规划，简单增加搜索还可能降低质量。[![](https://www.google.com/s2/favicons?domain=https://arxiv.org&sz=128)arXiv](https://arxiv.org/html/2608.03501v1)

这说明的不是“Agent 没用”，而是：

1.  高层规划和低层配置不能交给同一个自由文本过程；

2.  搜索只有被组织成任务化操作才有价值；

3.  实验设计整体目前不能获得默认执行权；

4.  它的一些子任务可以获得有限委托权。


而且这篇论文明确限定在计算机科学和 AI 论文中的一次性实验设计，没有覆盖自然科学湿实验、设备约束、安全问题，也没有评估实验结果反馈后的动态迭代。[![](https://www.google.com/s2/favicons?domain=https://arxiv.org&sz=128)arXiv](https://arxiv.org/html/2608.03501v1)

所以不能从它推出“LLM 无法做 AI4S”；合理结论是：

> **不能把“为一个陌生科研项目生成完整实验方案”当作当前的高可信自动化单元。**

## 文献搜索可以形成真实的生产力通道

OpenScholar 在它的多领域评测设置中，通过专业文献库、检索器和反馈循环提高了正确性与引用准确性；LEADS 的临床文献挖掘用户研究则报告，在筛选和数据提取中分别节省约 20.8% 和 26.9% 的时间，同时保持或提高质量。[![](https://www.google.com/s2/favicons?domain=https://www.nature.com&sz=128)Nature+1](https://www.nature.com/articles/s41586-025-10072-4)

# 什么样的 loop 才不是浪费 token？

可以设置一条硬规则：

> **每一次 Agent 循环都必须获得至少一个不是由模型自己生成的新 observation。**

有效 observation 包括：

-   新检索到的原文；

-   代码执行结果；

-   隐藏测试集得分；

-   模拟器输出；

-   仪器测量；

-   数据库返回；

-   人类反馈。


如果一次所谓 self-reflect 只是让模型重新阅读自己的文本，它大概率只是在重新排列已有 token。

更进一步，每个 Agent 模块都必须通过一个 **Agent Necessity Test**：

```
固定确定性流程
vs.
单次 LLM 调用
vs.
Agent 自适应循环
```

比较的不是回答好不好看，而是：

```
合格产物数量 / 人类小时
错误率
覆盖率
下游存活率
计算与实验成本
```

Agent 循环只有在扣除成本后显著优于前两者，才应该保留。SCOPE 中的无结构搜索会降低质量，而结构化 OptED 会改善结果，正说明“加 Agent”本身不是价值，**可测量的自适应增益**才是价值。[![](https://www.google.com/s2/favicons?domain=https://arxiv.org&sz=128)arXiv+1](https://arxiv.org/html/2608.03501v1)

# 面向 125 个问题，系统应当成为“科研委托操作系统”

它不再试图用同一条自主科研链回答所有问题，而是为每一个大问题绘制一张**自动化前沿图**：

```
Science 125 原问题
        ↓
Task Compiler
把问题分解成有类型的科研工作单元
        ↓
Delegation Router
├── 机械可验证 → 全自动
├── 可统计校准 → 选择性自动 + 抽样审核
├── 有快速现实反馈 → 边界内自主搜索

        ↓

        ↓

持续更新每个模型—任务—领域的风险、覆盖率和 ROI
```

基模升级时，不需要重写系统哲学。

```
旧模型：1% 错误预算下自动覆盖 42%

```

```
新失败样本
→ 加入回归测试集
→ 重新计算风险—覆盖率曲线
→ 收缩或取消相应权限
```

所以真正的不变量不是“发现缺陷—增加补丁”，而是：

> **能力测量 → 权限分配 → 在线抽样 → 漂移检测 → 权限更新。**

# 整个系统只需要五个部件

```
                    ┌────────────────────┐
                    │ 1. Research Contract│
                    │ 人定义目标和边界     │
                    └─────────┬──────────┘
                              ↓
                    ┌────────────────────┐
                    │ 2. Task Compiler    │
                    │ 拆成科研工单         │
                    └─────────┬──────────┘
                              ↓
              ┌─────────────────────────────┐
              │ 3. Delegation Router        │
              │ 判断：交给程序、Agent或人    │
              └──────────────┬──────────────┘
                             ↓
                    ┌────────────────────┐
                    │ 4. Agent Sandbox    │
                    │ 自主搜索、调用工具、试错│
                    └─────────┬──────────┘
                              ↓
                    ┌────────────────────┐
                    │ 5. Acceptance Gate │
                    │ 通过、重做、升级给人 │
                    └─────────┬──────────┘
                              ↓
                      Accepted Science State
```

## 1\. Research Contract：人类只在这里定义一次方向

它不需要很长，只回答五个问题：

```
研究目标是什么？
本轮不试图回答什么？
允许使用哪些数据和工具？
什么结果算有价值？
哪些决策必须由人类签字？
```

例如光伏问题：

```
母问题：
光伏电池的最终效率极限是什么？

本项目实际处理的子问题：
在已选定的单结吸收层假设下，识别稳定性和带隙具有潜力、
但关键实验数据不足的候选材料。

本项目不声称：
回答光伏技术的最终效率；
证明某种材料能够实现工业化；
证明带隙和形成能足以代表实际器件效率。

人类保留的决定：
代理指标是否合理；
是否进入真实合成；
如何解释异常结果。
```

仅仅写清楚这几句话，就能消除当前方案中“用带隙筛选材料，却声称在回答最终效率”的问题。

* * *

## 2\. Task Compiler：不生成答案，只拆工单

每个工单必须包含以下内容：

```
Task
├── 输入是什么
├── 输出必须是什么格式
├── Agent 可以调用什么工具
├── 如何验收
├── 错误会造成多大损失
├── 验收失败后怎么办
└── 是否允许自动写入系统
```

例如：

```
任务 T-017

目标：
从指定论文中提取吸收层材料、带隙、退火温度和测量效率。

输出：
结构化表格，每个字段必须绑定原文位置。

验收：
1. DOI 必须存在；
2. 每个字段必须有原文片段；
3. 数字和单位必须能在原文中找到；
4. 随机抽样审核错误率低于约定阈值。

权限：
高置信字段自动进入暂存证据库；
低置信和冲突字段进入人工队列。
```

这才是系统中真正的“原子”。

不是 `hypothesis agent`，不是 `reviewer agent`，而是一个个**可以明确判断完成或未完成的科研工单**。

* * *

# 三种权限，不再笼统讨论“信不信 LLM”

## 绿色工单：机器验收后直接通过

典型任务：

-   数据库查询；

-   代码执行；

-   单位换算；

-   统计计算；

-   文献元数据核验；

-   在已定义指标下筛选材料；

-   在模拟器中进行参数搜索。


例如 Agent 写了一段材料排序代码，只要：

-   在干净环境中能够重跑；

-   单元测试通过；

-   输入输出固定；

-   独立实现得到近似结果；

-   没有使用测试集信息；


就可以自动接收。

这里不需要人阅读 Agent 的推理过程。

* * *

## 黄色工单：经过校准，选择性自动通过

典型任务：

-   论文筛选；

-   实验条件抽取；

-   文献证据分类；

-   识别相互冲突的研究；

-   从自由文本中建立结构化关系。


处理方式不是全部人工审核，而是：

```
高置信结果 → 自动暂存
中等置信结果 → 抽样审核
低置信或冲突结果 → 人工处理
```

注意，“高置信”不是模型自己说的 0.95，而是历史测试得到的：

```
在同领域 500 个已标注样本中，
满足条件 X 的输出错误率约为 1.2%；
因此允许该类输出自动通过，
同时持续抽检 5%。
```

这就是**局部可信**。

* * *

## 红色工单：Agent 只能准备决策包

典型任务：

-   选择代理指标；

-   判断子问题是否真正回答母问题；

-   提出新的因果解释；

-   决定昂贵实验是否执行；

-   判断结果是否具有重大理论意义。


Agent 不能直接决定，只能输出：

```
Decision Package
├── 当前需要做什么决定
├── 可选方案 A / B / C
├── 每个方案所依赖的假设
├── 支持和反对证据
├── 预期收益
├── 成本和风险
├── 哪项新信息最可能改变选择
└── Agent 推荐及推荐理由
```

人的工作从“重新做一遍研究”变成：

> **只判断系统已经压缩好的少数关键分歧。**

# Agent 到底在哪里体现“智能”？

不是在最后写出一份长报告。

而是在一个工单内部，根据外部结果改变下一步行动。

例如：

```
第一次搜索
→ 发现关于材料稳定性的论文不足
→ 自动追踪被引用文献
→ 发现实验采用了不同湿度条件
→ 修改提取结构，加入湿度字段
→ 重新抽取
→ 发现原有候选排名对湿度非常敏感
→ 运行新的敏感性分析
→ 找出决定性缺失数据
→ 提出最低成本的补充测量
```

这就是有价值的 Agent loop。

相反：

```
生成答案
→ self-reflect
→ critic 评价
→ 再生成答案
→ 再辩论
```

但没有获得新论文、新数据、代码输出、模拟器结果或仪器观测，这通常只是 token 循环。

因此可以写一条系统硬规则：

> **任何循环若没有获得新的外部 observation，不计为科研进展。**

外部 observation 只能来自：

-   新文献原文；

-   数据库结果；

-   代码执行；

-   隐藏测试；

-   模拟器；

-   仪器；

-   人类反馈。

# 怎样防止系统一直吐垃圾、浪费 token？

不要用“运行了多少轮”评估系统。

只记录五个数字：

有效产出率\=Token 成本 + 机器成本 + 人类审核时间通过验收的科研产物​

具体指标：

指标

含义

Acceptance Yield

Agent 产生的候选中，有多少通过验收

Precision after Gate

通过验收的产物中，还有多少错误

Human Minutes per Artifact

每个合格产物消耗多少人工时间

Downstream Survival

产物进入下一阶段后，有多少仍然有效

Agent Lift

Agent 是否优于固定流程或一次调用

系统必须同时运行三个基线：

```
A. 固定程序
B. 单次 LLM 调用
C. Agent 自适应循环
```

只有当 C 在“每个人类小时获得的合格产物”上显著优于 A 和 B，才保留 Agent。

否则直接关闭该 Agent 模块。

这句话很重要：

> **Agent 不是默认架构，而是一个必须证明自身 ROI 的可替换执行器。**

# 基模进化以后，系统如何变化？

系统维护的不是“哪个模型最好”，而是一张**委托地图**：

```
                         GPT-X     Model-Y    固定程序
文献元数据核验            绿色       绿色        绿色
复杂实验条件抽取          黄色       黄色        红色
代码修复                  绿色       黄色        黄色
开放实验设计              红色       红色        不适用
模拟器内参数优化          绿色       绿色        黄色
因果机制解释              红色       红色        不适用
```

新基模发布后，只做三件事：

```
在历史任务上回测
→ 在真实任务中影子运行
→ 更新相应工单的权限
```

例如：

```
旧模型：
在 1% 错误预算下，可自动处理 38% 的文献抽取任务。

新模型：
在相同错误预算下，可自动处理 67%。

结果：
新模型获得更大的黄色/绿色覆盖范围。
```

后来研究发现一种新缺陷：

```
加入失败案例到回归测试
→ 重新测量错误率
→ 权限从绿色降为黄色
```

因此，你要抓住的不变量不是某个 Agent 框架，而是：

> **任务实测、风险分级、权限授予、持续抽检、权限回收。**

# 第一版系统不要再做八步完整科研闭环

直接砍成四个模块。

## 模块一：科研工单编译器

输入一个人工确认的 Research Contract。

输出 10—30 个有明确输入、输出、验收方式和风险等级的工单。

## 模块二：Agent Sandbox

Agent 自由搜索、调用文献库、数据库、Python、模拟器。

内部失败不重要。

## 模块三：三个验收器

只先做：

```
Citation Verifier
检查引用、原文位置、元数据和字段一致性。

Computation Verifier
重跑代码、检查测试、单位和数据依赖。

Benchmark Verifier
在隐藏历史任务或保留数据上检查结果。
```

## 模块四：委托控制台

界面只展示：

```
绿色：自动完成了什么
黄色：哪些内容被抽检
红色：现在需要人决定什么
节省了多少人工时间
每类任务当前错误率是多少
Agent 相比固定流程提升了多少
```

这比展示“多智能体讨论过程”“假设树”“AI 承认自己错了”更能回答评审的问题。

# 第一版产品应该输出什么？

不是：

> 当前证据最强的结论。

而是四份非常具体的东西：

```
1. Accepted Evidence Set
经过验收、可以直接使用的证据和数据。

2. Reproducible Computation
可以重跑的分析、排名和敏感性结果。

3. Unresolved Decision Queue
真正需要科学家判断的少量问题。

4. Next-action Candidates
经过成本、风险和信息价值排序的候选行动。
```

其中前两项真正替人完成工作。

第三项压缩人的认知负担。

第四项发挥 Agent 的搜索和规划能力。

# 最后把整个系统压成一句话

> **把 LLM 用于大规模搜索和候选生成，把自动化建立在“生成昂贵、验收便宜”的任务上；以科研工单为授权单位，让通过实测的任务自动完成，让无法廉价验收的关键判断以决策包形式交还给人。**

再形象一点：

> **不要造一个 AI 科学家。造一个科研编译器：人写目标，Agent 搜索，验证器验收，只有合格产物进入科学状态。**

你下一版架构图里，应该删掉“八步模拟科学家”，换成四个大框：

```
工单编译 → 智能搜索 → 自动验收 → 动态授权
```

这四个框，就是整个系统的骨架。
